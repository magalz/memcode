# First-use acceptance

Use a fresh profile and a disposable project. Leave existing projects and
provider accounts alone. The website walkthrough uses example data; it does
not establish these desktop results.

1. **Install and open MemCode.** It opens without a separate Node.js or
   Memtrace CLI installation. No worker starts automatically.
2. **Connect Memtrace beta.** Approve the intended account in the browser.
   The app prepares its local engine and shows a connected state. Cancelled or
   expired consent offers a clear retry without adopting another account.
3. **Add a project.** Choose an existing folder or start from a brief.
   Existing files are preserved. Local analysis reports its actual readiness.
4. **Connect one worker.** In Workers, review and approve an installed coding
   tool. Set its default permissions. Provider sign-in remains with that tool.
5. **Create an epic and one story.** Give the story a clear outcome and a way
   to check it. The new card appears in the chosen lane.
6. **Start and follow the work.** Inspect the proposed route, start the worker,
   then follow its conversation. Send a follow-up while it works; it appears in
   Queue and can be edited or cancelled before pickup.
7. **Review the result.** Open Changes and a saved artifact. Save a selected
   review comment, then deliberately include it in a follow-up. On Windows,
   check the shared live browser; check a persistent terminal where present.
8. **Change account or sign out.** Finish active workers first. Local work
   remains saved. Beta sign-out pauses analysis and never selects a paid CLI
   plan automatically.

## Collaboration, once Team creation is enabled

1. **Create a team and share the current project.** Sign in with the intended
   Memtrace account. No server address or setup secret is requested.
2. **Invite a teammate.** They accept in their existing installation and see
   the current board without creating an empty project.
3. **Work on this computer.** The teammate chooses a checkout location, checks
   Git access and approves their own worker. Joining alone starts no worker.
4. **Claim and share.** A second worker cannot claim the same story. Publish a
   small report; the teammate can open it. Reconnect and confirm the accepted
   board changes and result remain available. Git carries source changes;
   graphs, terminals and browser sessions stay local.

One account on two devices checks device synchronization. Separate real
accounts are needed before calling a test verified multi-person collaboration.
